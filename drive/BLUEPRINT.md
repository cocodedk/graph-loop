# The drive loop — blueprint

How to build this loop again, anywhere. What each part is, why it exists, and the
order that makes it safe to leave alone. The story of how it was learned is in
`DIARY.md`; the rules are in the repository's `CLAUDE.md`. This file is
the design.

Built 2026-08-28 by Fable and Codex under the owner's direction, extended since by
the slicer and triage below. The
suite proves its own size rather than pinning a number here: every file under
`tests/` asserts its own `EXPECTED_TESTS` count against what `unittest`
actually collected.

## The idea in one paragraph

A backlog of atomic tasks is worked to done by two models that never trust each
other: a reviewer (Codex first, then Claude — a review is read-only, so any agent that
can read the repository can give one) refuses any task whose gate could pass
without the work, a builder (Claude Opus, effort rising from high toward
xhigh as rounds are lost, never `max`) does one task in a private worktree, the gate — a command whose exit
code is the verdict — decides, the reviewer reads the finished diff, and only
then is the work committed to a campaign branch. Everything the loop says, hears
and measures is written to an append-only log, and a watchdog reads that log to
catch the loop going through the motions. A person is needed only where a task
says so, and the loop says out loud when it needs one.

## The parts, in dependency order

| part | file | one job |
|---|---|---|
| durable write | `lib/durable.py` | a record the next step depends on, on the platter before that step runs: written beside, renamed, and the file, its folder and the entry naming every folder the write itself creates all fsynced before it returns. Used by the salvage diff and the card pointing at it (before the tree is removed), the pending-keep note (before `update-ref`) and the card that says a live call is open (before the call). The slicer's molecule files go down this way too — and the backlog folder that names them, because a rename left in the page cache loses the child whole — before the parent card is settled over them. The event log is not written this way: an fsync per append costs every append and does not answer what broke there — a reader that raised on one cut line — except where a caller asks (`Workspace.event(synced=True)`, `durable.append`), which today is TRIAGE's `triage_model` marker: the record that says a task has had its one paid classification, on the platter before the call it pays for |
| backlog | `lib/backlog.py` (+ `backlog_status.py`) | which task may start: dependencies met, files disjoint, humans respected. What a status MEANS is `backlog_status.py`, shared by the picker, the doctor and the board: done settles, a sliced parent settles when every piece it names exists and has settled, a dropped card settles, a refused one blocks. A slice inherits how its parent is judged. Every status × cause pair triage can produce has a next actor (`is_wall`, and `backlog_decision` for whatever no actor takes): a red-first `green_already`/`unprovable` with a contract cause goes to the slicer, `out_of_scope` names no cause of its own — the fence sees where bytes landed, not whose fault that was, so the card goes back once and only the model's reading of the paths sends it to the slicer — and a repaired card goes back to its builder IN THE SAME WRITE as its gate — apart, a death between them left the gate repaired, the card still parked and its refund lost — with the rounds its broken gate cost — counted as `gate_rounds`, written only where a gate failure charges a round, which also clears any refund watermark left from before that counter existed, never refunded twice — while one whose remaining rounds went on something else is handed to a person rather than left `todo` for a picker that will not offer it |
| tree backlog | `lib/backlog_tree.py` (+ `lib/molecule.py`) | the storage format the slicer writes and the ordinary backlog reads and writes transparently (`Backlog.is_tree`, true when its path is a folder): one directory per molecule, `molecule.md` as the parent card, `NN-name.md` atoms running in stage order (equal numbers run together) — the number is read as a number, so 99 runs before 100, and `molecule.ordered`/`molecule.atom_id` is the ONE reader of an atom's file name, used by the tree's read and by its write alike — a molecule appearing whole or not at all — built under a dot-name, renamed into place. The naming law every atom must obey — a name it uses must already exist in the repository, or an earlier atom in the same molecule must create it — is `lib/molecule.py`, asked of the repository itself, never of a list kept beside it. A molecule cut from a parent records that parent's contract digest beside its lineage (`sliced_from_contract`, the child taken back out of the parent's waits so both sides read it the same way): `sliced_from` says which card it was cut from, and this says which VERSION, and `sliced_atoms` digests the plan inside the folder itself — every file it holds, read for the fields the slicer's own answer declares (`tree_stale.PLAN`), so a card that has merely STARTED is still the molecule that was reviewed and an edited goal or gate is not. Finishing an interrupted publish (`tree.recover`, the slicer's recovery entry, over `roll_forward`) settles the parent only while both still stand — a rewritten parent, an edited child, or a molecule that names neither, is refused as `StaleChild` and RETIRED once (`tree_stale.retire`, under the backlog lock, the staleness asked again there and the molecule kept whole as `.stale-<name>.xxxx`, which the reader does not read, with `retired.txt` saying why): refusing it cost nothing and changed nothing, so the same stale child was selected every run and its parent stayed the slicer's for ever (astra's round-4 finding 9). A lane building any card inside the folder holds the whole molecule and the retirement refuses as `CardMoved`, uncharged — and the graph is checked again there, under the publication lock: `slicer_law.assert_recovered_order` reads the rows as they stand — every wait the published molecule already carries, its atoms' included — and adds only the one edge still to write, the parent's wait for its child |
| resources | `lib/resources.py` (+ `accounts.py`, `models.py`) | the conveyor belt: every resource any part may spend, as agent + account + model. `belt(job)` gives build, plan, review and decide their own order — `decide` is the review belt under its own name, because a decision reads and writes nothing either, and its caller spends the first rung at max where a reviewer never does; `Exhausted` remembers what has run out — a limit belongs to the ACCOUNT and skips its other models, a capacity refusal belongs to the MODEL and skips it on every account. Nothing names a resource in code: `accounts.py` and `models.py` are tables, and `DRIVE_ACCOUNTS`, `DRIVE_BUILDERS`, `DRIVE_REVIEWERS` override them |
| providers | `lib/providers.py` (+ `provider_call.py`, `effort.py`, `provider_words.py`, `provider_codex.py`) | one builder call, one codex call and what their answers mean. `provider_codex.codex_text` is the codex call itself — read-only, prompt on stdin, through the same runner every child goes through, and no spend, because codex reports none and unknown is not zero. Reading it is the caller's: the review decodes ACCEPT/REJECT from it and the slicer reads its own closed JSON, and neither grades the other's answer — sending a plan through the review door returned `malformed` every time — `provider_words.py` tells a usage limit (the account's) from a capacity refusal (the model's) apart, so the belt in `resources.py` knows which one to skip; the effort of each is chosen per task by `lib/effort.py` — the card's own weight (files, a live gate, a long contract, a commander's mark) plus every round it has already lost, never below high for a builder or medium for a reviewer, and never above xhigh for a builder or high for a reviewer — `max` on neither; a rebuild round RESUMES the previous call's session (same work, findings on top), a new task or a re-slice never does — and a call proved unstarted records no session at all, however loudly its refusal names one, because there is nothing in it to resume and the card would read as one a call had run in. A verdict needs one distinct answer in every format the reply uses, from a provider that exited 0 — two `REVIEW:` lines that disagree, a JSON answer and a `REVIEW:` line that disagree, a key given twice, and a JSON answer that does not decode — cut off part way, or broken with a readable one above it — are all malformed, and a non-zero exit is no answer; a line that opens an object is decoded before its keys are read, so an escaped `review` key is that key and an object with no such key is prose, not an answer — and a DONE that sets `needs_person` or `blocked` parks the card. The claude reviewer runs `--tools Read,Grep,Glob --strict-mcp-config` (`tools.READ_ONLY_FLAGS`), the one list the slicer planner reads too. Every call this loop pays for goes through one function, `provider_call._run` (`providers._run` stays its front door): it merges the account's overlay onto this process's environment and hands the child a scratch directory of its own as `$TMPDIR`, removed when the call returns — read-only trees a build left behind included, which a removal that swallows its own errors leaves whole and says nothing about; a scratch that still will not go is named on stderr and left, never raised over the answer the call just bought or the timeout the caller was about to read — a builder runs its card's gate while it works, and that gate writes to `/out` when TMPDIR is unset |
| gates | `lib/gates.py` (+ `runner.py`) | run a gate; the exit code decides; prove it red before anyone builds. Every gate and provider child process is started and killed by `runner.py` alone — it leads its own process group, so a timeout reaches whatever the child spawned too, not just the child itself; shared by `providers.py` and by the claim-kill path (`workspace_kill.py`). The group is ended on every return, success included — a job started with `&` never outlives the call — and a group that survives SIGKILL is an error, never a pass. Every such child is bound to the driver's own life (`PR_SET_PDEATHSIG`): a driver that is hard-killed takes its builders, gates, planners and slicer with it, instead of leaving them running and spending on a worktree a restart can hand to a second builder. That binding reaches the direct child only; a job it started with `&` outlives its own leader, and a scope for the whole group (a cgroup, `systemd-run`) is not built. A CODE gate's TMPDIR is its own scrubbed home, removed when the gate ends; a LIVE gate inherits the environment and its scratch is not swept |
| workspace | `lib/workspace.py` (+ `workspace_claims.py`, `workspace_flags.py`, `workspace_alerts.py`, `workspace_kill.py`) | the campaign's memory: rotating JSONL events, timed steps, artifacts and alerts; one space-level lane-turn context makes the shared event writer stamp every event in that turn with its ID. `workspace_alerts.py` records a candidate a render displayed in `ALERTS.shown` and a person's confirmation in `ALERTS.read`. Nothing the loop does waits for that confirmation: applying a decision RESOLVES the exact alerts about the subject it decided — their line numbers, in `ALERTS.resolved` — so they stop asking and leave the board on their own, while the cursor stays a person's and every unrelated or fatal notice standing between them is untouched. An alert nothing has answered still shows red on every later tick. The stop and restart flags are read between tasks and consumed once — a driver is never killed mid-turn. The claims file says who works on what now; a claim is alive by the claimant's own pid, never by its process group, because the driver shares its group with the supervisor that restarts it. A claim is written to that file first and recorded as an event after, so a lane owns one from the moment it ASKS for it, not from the moment the call returns: it releases what it asked for, a claim whose event write failed included, and a failure anywhere in asking is heard like any other lane failure (`lib/lanes.py`) rather than escaping the thread and leaving a live claim on a card nobody is building. What a lane never held it never writes: the failure is still evented and alerted, but the card keeps the status its ending gave it. The report of a lane's failure is written one piece at a time — the event, the alert, the parking, the release each on their own — because whatever killed the lane is often what stops it being written down: a journal that cannot be written AT ALL still parks the card and lets the claim go. What could not be recorded is then raised to the driver once the lanes are joined (`RuntimeError`), because the log is the product and a turn nobody could write down is not a turn to build the next one on. Killing a claimed process's whole tree freezes the group first (SIGSTOP) so nothing it spawned can outrun the kill (`workspace_kill.py`). A last line a crash cut in half is repaired under the lock (`workspace_log.py`): the bytes stay as a `log_truncated` event and the file is replaced atomically; a broken line anywhere else is an error, never skipped. One driver per campaign: `driver.lock` is held for the process's life and a second driver exits with a message |
| worktree | `lib/worktree.py` (+ `worktree_refs.py`, `worktree_provision.py`, `hooks/reference-transaction`) | one checkout per task, a shared-object clone whose refs are its own, so nothing a builder does to refs can reach the repo or another lane; the scope check; the live-stack lock; inside the clone git's own `reference-transaction` hook refuses a commit, a branch or a switch to a new branch, and after each builder call HEAD must still be the base or the tree is discarded and the round fails closed. A tree whose HEAD moved is never REUSED — it cannot be read as the base plus edits — but what it holds was still paid for: `worktree_refs.save_and_go` is the one door both deletions go through (the builder's own move, and a gate's — `loop_judge_retry`), writing the diff down against the RECORDED base, not HEAD, because HEAD is what cannot be trusted there and edits inside a builder's own commit leave nothing in a diff against it. A kept tree whose edits conflict with the moved base is paid work the same way: its diff is written down (binary-safe) and pointed at from the card (`lost_edits`, a list) before the tree goes, and every later round is told to reapply it; done clears the pointers. A save that fails keeps the tree — it is the only copy — and names it in `edits_unsaved`. The card names its tree (`rebuild_from`) only once a builder is paid on it — a death before red-first leaves nothing to resume, a death mid-build resumes the tree — and a refusal before reading removes only a tree this call cut. A living holder keeps the live-stack lock whatever task the record names. A lock file that names no holder anyone can CHECK — empty, garbled, unreadable — is held all the same (nothing abandons a claim on a doubt) and the file stays, because what cannot be read cannot be cleared; but it is not a living holder either, so the card no longer waits on it for ever: the failure is recorded (`live_lock_unreadable`) and after `LOCK_WAITS` turns the card carries that reason and a status no picker offers, which is how the plan phase comes to own it (astra round 4, finding 10). A lock that reads plainly again clears the count. That lock lives with the STACK — one file per compose project (`drive-live`), under the user's own home from the passwd database so no environment variable can move it — not in the campaign directory, where a second campaign simply had a lock of its own while both drove the same stack. Reading the holder, clearing a dead one and publishing a new one happen under one `flock`, so two drivers that both meet the same dead lock cannot each publish; and it is given back by the driver that took it, or by anyone once its holder is gone, never by a driver that never held it. NOTHING in the environment names that folder and nothing may be added that does — two names for one lock is two drivers on one stack, which is what `TMPDIR` and then a `DRIVE_LIVE_LOCK` override each turned out to be. `worktree_lock.stack_lock()` is the one door, so a test isolates itself by standing in for `worktree_lock.shared` — the suite's guard (`tests/tmp_root.py`) does it once for every rig that builds a `Loop` |
| distress | `lib/distress.py` | the builder's last line: JSON with fixed flags, or UNCLEAR and a person is told — only the last line that opens an object is read, whether or not it closes, a key given twice is not a result, and a DONE that sets `blocked` or `needs_person` parks |
| loop | `lib/loop.py` | one task start to finish: held? → lock → red-first → then `loop_contract.py` (contract review), `loop_steps.py` (build, scope) and `loop_judge.py` (gate, diff review, rebuild rounds, keep); the tree this round runs in — the paid one it continues or a fresh cut — is `loop_tree.py`, and the one guard every ending passes is `loop_moved.py`; prompts in `prompts.py`, the contract's own text and identity in `contract.py`, shared names in `loop_types.py`. Every ending — keep, reject, harness fault, a no-files card's green gate, a refused contract, a red proof that could not be made, a gate's scope fault, a card sent for re-slicing, and a lane's own death (`lanes.py`) — re-reads the card under the backlog lock and writes in the same hold: a hold, a status, a `needs` or a contract edit a person or another writer made meanwhile stands and the work is kept (`card_moved`), and the round ends `held` so no later writer overwrites it either — the live-card park and the lane's re-slice both stand back. A round that has bought nothing yet — a first round's contract review or red proof — leaves no tree behind when the card moved (`moved_first(paid=False)`), because a recorded path is not a paid tree. `contract.MOVED` is the one list of what makes a card the same card, read two ways — `moved_under` names the field that changed, `revision` names them all at once. Both reviewers read the whole accepted contract, one text (`contract_text`): note, gate, helper verbs, what the card waits for, the names it uses and creates, the phrase its red proof must print, the card it was cut from (`contract.REST`), the REQUIREMENT the card was granted under — its original goal, its done-when and the sources it cites, frozen by the host BEFORE anything can rewrite it (`contract.frozen_requirement`: at the first contract review in `loop_contract`, and on both ways out of a replan, because a card refused for its names is rewritten before any review) and never written by a model — and how many `recorded rewrites` the card carries, which is `rewrite_history`; so a rewrite of "prove A and B" into "prove A" is visible to both reviewers instead of being judged on A alone (astra round 3, finding 8, and the contract prompt asks them to refuse a rewrite that proves less unless its note names the recorded decision that narrowed it). A card carrying no requirement has not been read under this contract text, whatever digest it recorded, so `already_read` sends it back to the reviewer and the freeze happens there — an acceptance stored before the freeze existed would otherwise skip it for ever. And for the diff reviewer the previous round's findings and the digest. The digest covers every field that text shows, so editing any of them sends the contract back to the reviewer — and `needs` is read there, sorted, rather than a second time in `MOVED`. Each value is written as JSON, so a note that spells out another field's line is a note and not that field; non-ASCII characters remain readable, while JSON still escapes quotes, backslashes and control characters. A round that has bought nothing yet — a first round's contract review or red proof — leaves no tree behind when the card moved (`moved_first(paid=False)`), because a recorded path is not a paid tree. A rewrite freezes it too, from the card as it stood before a single new field is written, so a card no reviewer and no replanner ever saw still says what it was granted under after its goal is narrowed; a requirement already on the card is never re-frozen from the narrowed one |
| keep | `lib/keep.py` (+ `keep_tree.py`, `keep_gate.py`, `keep_remote.py`, `keep_pending.py`) | accepted work becomes a commit on the campaign branch; the next task starts from that tip. The staged names are read NUL-terminated and decoded one at a time (`keep_tree.py`), so a name git would quote — `café.py` — is committed under its real name instead of dropped. Before committing a CODE card, the candidate tree is checked out on its own and proved against this card's gate, the six most recently kept CODE cards' gates, and — however far back it was kept — the gate of every CODE card whose own files this card edits, deduplicated (`keep_gate.py`) — bounded regression coverage, not full proof that nothing else broke; a clash follows the capped rebuild path. A live card's keep re-runs no gate at all — its gate acts on the stack, and it ran alone. `keep_remote.py` pushes the branch; `keep_pending.py` is the crash-recovery note for a keep whose branch moved but whose card-write never landed — a note is stale, and removed, only on git's own "no" (`merge-base --is-ancestor` exit 1); any other non-zero is a read error, so the note stays, is left out of the answer and is said on stderr (`keep_pending_unreadable`, in `run.log`) for the next turn to ask again; the turn top closes such a keep only while the card still matches the `keep_revision` the keep was made against — read, checked and written in one backlog lock hold, and an ABSENT revision is unbound, never a match — and otherwise the keep is written off mechanically: a durable receipt naming the commit and both revisions, that exact note retired, the commit left on the branch and the newer card left as it stands (`publishing.supersede`). The combined gates run in a private clone of the repository (`Worktree`, the same checkout a builder gets: its own `.git`, the ref hook, the runtime material), so a ref write git makes from inside the checkout lands there and is thrown away with it — the linked worktree this replaced shared the repository's refs, and a gate that moved `refs/heads/main` moved the real main line. A gate line naming the repository's own `--git-dir` still reaches those refs, so they are watched rather than walled off. Each combined gate runs against one fingerprint, read before it and again after: the checkout (mode and content of every path the scope check reports, the index entries git has been told to skip, HEAD, and the clone's own copy of the main-line branches) and the repository's own protected branches — each of those refs read with its symbolic target as well as its commit, so an alias made at the same commit is not invisible, and the protected names resolved in the repository, because the clone has no remote to name them. Any change to any of it refuses the keep. That is detection AFTER the mutation, not prevention: the write has already happened, and only a read-only bind of the repository under the gate would stop it. Ignored paths, build artifacts, and an edit that restores a file's stat data exactly are not checked. A combined-gate failure is charged to this card only when its diff turned the gate red; a gate that is red on the tip without the diff — or one that edited the tree it judged, which is a defect on its face and is raised as a combined-gate failure so the judge can route it rather than escaping every handler — is defective, and its owner — if it is still done — goes back to `todo` for the repair, with the reason on the card and its contract read again before anything runs that gate and any hold a person put on it passed back explicitly, while this card gains the owner in its `needs` and waits there instead of retrying into quarantine (`loop_judge_gates`). The destination is never main, master, the repository's default branch, an alias, or a branch a worktree holds — checked when the keeper is made and again right before `update-ref`. A branch name loses a LEADING `refs/heads/` and nothing else (`keep_branch.plain`, the one reading for the keeper, the note, the push and `init`): cutting at any `refs/heads/` turned `campaign/refs/heads/fresh` into another branch. And every lookup of it reads that one ref and nothing else (`keep_branch.resolve`, `show-ref --verify`, shared by the keeper, `keep_branch.tip_of`, the slicer's checkout and `init`; the board's base flag makes the same call through its own runner, `keep_branch.resolve_argv`, counts from the commit that came back, and asks `show-ref --exists` (`absent_argv`) whether a ref it could not read is missing or broken — only its exit 2 is 'not cut yet'): `rev-parse` answers with a TAG of that name — even of the full ref's name — so a tag made the keeper start the next task from it, and said a branch nobody had created was already there. |
| watchdog | `lib/watchdog.py`, `lib/watchdog_spin.py` | spinning, stuck, futile — read from the log, measured in time since progress, never money; futile alerts, never stops. The watchdog and `needs_slice` read the log through the same two rules, so they never disagree: two endings are the same when their task, step and whole reason match, with ticking counters blanked (`view_stamps.TICKING`) and spacing collapsed — never a prefix of the reason; and both count only the endings since the card's last boundary (`spends_failures`: a quarantine, a spent spin, a replan, or a slice that finished with rc 0), so old failures never poison a rewritten card |
| replan | `lib/replan.py` | a refused CODE contract is rewritten from the reviewer's findings at the top of a turn, twice at most and never wider. An answer holds goal, files, done_when and gate and nothing else, checked before anything reads it: a key nobody stores is still read on the way past, and `needs: 1` reached the graph check and raised, ending the replan with its round unspent (Codex, 2026-09-08). What the rewrite may do to the card is then the shared validator (`rewrite_guard.check_rewrite`, one validator, one caller now): the file grant is a list of names, it only narrows, and a card that changes code is never handed back changing none — `files: []` used to pass, and with a narrowed goal and a passing gate the card became an evidence card with no builder, no red proof and no diff review (astra round 3, finding 7). The planner MAY rewrite a CODE gate, and must when the refusal is about the gate — 142 of 153 contract refusals were, and a repair forbidden to touch the gate hands back the card the reviewer just refused, for ever. A rewritten gate is marked `gate_reviewed_first`, and the loop reviews the contract BEFORE red-first runs it, on a rebuild round too: red-first executes the gate, and planner-written shell has been read by nobody until that review. A LIVE gate is fixed and shown to the planner as fixed. Every answered refusal costs its round and is tried again in the same turn, the next planner reading every earlier reason; each planner call is recorded on its own; the planner has no tools and no MCP server. A LIVE task's contract is never rewritten — it is the commander's. A crashing planner used to leave ownership and both counters where they were, so `replan_refused` stood in the record turn after turn (astra round 4, finding 8). The card-moved guard is asked before the charge, not after it: a round charged to a card somebody dropped while the planner ran is the same bad write as a rewrite stored on one; each planner call is recorded on its own; the planner has no tools and no MCP server |
| graph builder | `../slicer/branches.py` (+ `../slicer/speccer.py`) | what turns a project into something the slicer can read, before any loop runs. The BRANCH WRITER takes one project brief and writes the branches a campaign is planned from: a branch is one capability a person would name, and its boundary is settled by one question — can this branch's acceptance be observed with every other branch absent? If yes it is a branch; if no it belongs to the branch beside it. Acceptance is written in words and never a gate, because the slicer derives gates from acceptance and the loop still proves every gate red before anyone builds. One `NN-name.md` note per branch, whole or not at all — a half-written branching is a graph nobody planned — and every name is checked path-safe before the first byte is written. An independent reviewer, never the writer, refuses a branch nobody can observe, a branch whose acceptance needs another branch present, two capabilities in one branch, an invented fact and any authority the brief does not grant; `NEEDS_PERSON` is a terminal gap and not a queue, like the speccer's. The SPECCER then turns one branch goal into one small source spec, written as a note in the same vault and linked back to its branch (`--branch`), because the graph has no root without that link. Branch, then spec, then cards: each layer is a vault note and the wikilinks between them are the graph (SLICER.md § 0). Standalone, like the speccer: no service stands behind either, and both run in the plan phase with the driver stopped. |
| slicer | `lib/plan_phase.py` (+ `lib/slice_turn.py`) | the PLAN PHASE, and nothing a build turn does: `drive-goal.py plan` slices until the graph stops growing and builds nothing, `drive-goal.py run` builds and plans nothing, and the two never overlap — the slicer used to run at the top of every driver turn, which is the two phases mixed by construction. Exhaustion is read from the backlog, never from what a call said about itself: the phase ends on the round that adds no card. Each round hands one stuck CODE card, or — when nothing is startable — the next gap in the campaign's declared approved sources, to the standalone slicer (`slicer/slicer.py`, `slicer_law.py`, `slicer_state.py`), run through `runner.py` like every other paid child — and the slicer's own planner calls (`intelligence.ask`) go through it too, so the whole chain, driver to slicer to planner, dies with the driver —, against a clean detached checkout of the campaign branch tip (`lib/clean_tree.py`, the one function that cuts one), with the target's whole lineage of findings and its kept worktree's diff copied in as evidence; the checkout and the temp directory holding it both go when the call ends, however it ends. A slicer call can take two hours, and no builder waits any of it out: the driver is stopped while the phase runs, and the phase is over before a builder starts. A card whose own dependencies are broken is never the target either — a need the backlog does not hold, a ring of needs, a `sliced` parent cut into no pieces (`backlog_decision.broken_wait`, one predicate and not a copy of it): `is_wall` reads the card's shape and never its needs, so such a card was this call's target even though the slicer's own law would refuse a plan whose external needs are not there — three paid rounds for the same answer. It is skipped uncharged, with a `slice_skipped` event naming the broken wait. ## The task contract

```yaml
- id: T11.principals
  goal: one sentence, one idea
  why: what it costs us that this is not done
  status: todo          # the picker offers only todo
  needs: [T11]          # ids that must be done first — only real dependencies
  files: [ ... ]        # everything the gate can fail on, and nothing that judges it
  gate: |
    set -e -o pipefail
    (cd simulation/tests/idp && timeout 600 python3 -m unittest ...)
  done_when: what the gate proves, and nothing more
  note: traps, the source of truth, what to do instead of guessing
  # optional:
  uses:    [simulation/scheduler/app.py:items]      # names this card leans on: file:text
  creates: [simulation/scheduler/app.py:observation]  # names it puts there for later cards
  gate_files_are_the_work: true   # writing the test IS the deliverable — tell the reviewer
  gate_has_side_effects: true     # the gate performs a live run: no red-first, take the lock
  blocked_by_human: true          # never started; shown as held
  # written by the loop, never by hand:
  rebuild_round: 1                # a rejected diff's next round (todo again)
  rebuild_from: /tmp/drive-…/task-T24   # the worktree that holds the work
  rejections: [ ... ]             # every reviewer finding so far, oldest first
  finished: {phase: gate, tree: …, base: …, contract: …, diff: …}  # a phase this tree already passed; read once, then dropped
```

Gate rules: every path relative to the worktree — except a live gate's helper (the main checkout's absolute `sc` by law) and a system path; every stage in its own
subshell `(cd … && …)`; its first line, alone, is exactly `set -e -o pipefail`; the
verdict is the exit code; it must fail today for the reason the task exists.

A gate's own scratch has an owner: it goes to `$TMPDIR/…` or `$(mktemp)`, the home
`run_gate` gives it and removes when the gate ends. Never a fixed `/tmp` name —
two runs of the same gate then share one file — and never a `$$` name, which
leaves a fresh file behind on every re-run, and a kept card's gate re-runs on
every later keep. `slicer/gate_output.py::unsafe_gate_sinks` is the one author of
that rule: it refuses a new gate that writes anywhere else, and
`tests/test_gate_scratch_is_owned.py` asks it — never a second reading of it —
of every non-live card already in the backlog. The doctor does not see this: it
excuses a redirect or `tee` target as the gate's own scratch, which is how
twenty such gates stayed invisible until astra's round-3 finding 19.

Five cards fail that validator today for a different fault: their gates write
into the worktree they judge (a generated spec file, a mutant tree cut with
`mktemp -d ./…`, a file inside the tree it judges) rather than outside the
driver's home. Four more were on that list and were never that: they called
`mktemp -p /tmp`, the host's own /tmp, which is finding 19's leak wearing a
variable — their gates call bare `mktemp` now, which follows `$TMPDIR`.
The five are named in that test's `KNOWN` set, which fails on a new one and on a stale one alike, and
they are their own finding — not part of 19. Each excuse is bound to the digest
of the exact gate text it excuses, never to the card id: a new leak appended to
an excused gate reads as new work rather than riding in on the name.

## The order of one task, and why each step is where it is

1. **held?** — a human hold is checked before anything costs money.
2. **lock** — liveness is declared (`gate_has_side_effects`), never inferred from missing files. A live card runs alone because it holds the one shared stack; a no-files evidence card also runs by itself, for a scheduling reason: with no files there is no edit for a lane to build, so its gate runs on its own, one at a time.
3. **gate ownership** — a builder that may edit the test judging it is refused
   before a review is paid for, unless the task declares the test is the work.
4. **names** — every name in `uses` must be in the repository already, or a
   card this one waits for must say it `creates` it. A card that names a thing
   nothing makes cannot be built by anyone, and refusing it costs a file read
   instead of a model call: `T26.facts-spec` named a durable field no producer
   emits and was refused fourteen times before this check existed.
5. **prove red** — a gate that has never failed proves nothing; skipped only
   when the gate itself performs the work, on a rebuild round (it was proved
   red before round one; a rebuild round whose gate is already green in the
   kept tree is not a fault — the finished work goes to the builder with the
   standing findings and then to the diff review), or for a no-files, non-live card, whose gate is
   never proved red: it runs once, after the contract review, straight to
   done or failed.
6. **contract review** — the reviewer reads the task, not the code; most defects
   die here at the price of one review.
7. **build** — the builder walks `resources.belt("build")` until one answers: every
   account, and for each, every builder model. It ends with one JSON line of fixed
   flags. The walk continues ONLY when the resource refused before reading — an
   expired session, a usage limit, a model at capacity — because anything else
   means the resource answered and another would spend money repeating the
   failure. A live task is called once beyond that: a call that reached the model
   may already have run a helper verb, so it walks on only when the answer PROVES
   it spent nothing — zero cost, zero tokens, zero denials, all three present. A
   missing number is unknown, not zero. Every resource refusing leaves a live task
   held for a person and says the stack is untouched, because it is. A live task's builder
   (`gate_has_side_effects`) is handed the stack through the helper
   (the repository's own command tool, `DRIVE_HELPER`: run, declare, journal, reject, story, target-state,
   reset-target, rebuild, free) instead of a container ban, and its allowlist
   IS the boundary (`lib/tools.py`), three fences deep: (1) the live guard,
   a PreToolUse hook (`lib/live_guard.py`, installed by the provider with
   `--settings`, by the main checkout's path) that lets a Bash command run
   only when it starts with one of this task's exact commands — the helper
   plus each `helper_verbs` entry — a verb with the arguments the contract
   fixed is the WHOLE command ("free prd-app-04" admits nothing more), a bare
   verb is open for the run id born in the task ("journal *") — and
   cat/ls/head/tail, with no shell control character; an entry is one plain
   line; a guard that cannot read the call denies (proved live: docker by
   name, by absolute path, wrapped in env, and chained after cat were all
   denied); (2) allow rules for the same commands, Read/Grep/Glob, and Edit
   on the task's own files; (3) deny rules for the raw stack against an
   inherited allow, and for Monitor and Workflow, which run commands of
   their own. The hook runs for EVERY tool: only Read/Grep/Glob/Edit/Write
   and Bash exist for a live task — an inherited or MCP tool is denied by
   name — because an allowlist only adds to what a session inherits. Only
   journal/story/why may be bare (their run id is born in the task); a bare
   run, rebuild, reject or reset-target grants nothing — reject takes the
   finding and the target the task declared, and the helper resolves the one
   pending run for them. A live builder is called once; a call that did not
   return (a limit, a crash) is no proof the stack is untouched, so the task
   goes to a person (`live_call_lost`) instead of a retry. The planner that
   rewrites a refused contract runs with no tools at all. `newpkg`/`next` can never be
   named; a run id born in the task is bound by the gate. The contract review
   sees the verbs and the planner cannot add to them; a rewrite naming a raw
   stack word costs the round it is and the next planner reads why. A code
   task keeps its shell. The gate
   still proves from durable state what the task did. The
   destructive verb resets the dev target once, ever, as the recorded ruling
   allows: it refuses unless the volume still carries its original creation
   instant, and builds the target's image from the clean head-build worktree
   before it touches anything. Every helper argument is shape-checked before it
   reaches a database, a container or a door.
8. **flags** — BLOCKED/PARTIAL is believed: worktree kept, alert raised, person
   told. UNCLEAR alerts but the gate still judges.
9. **scope** — anything written outside the task's files refuses the work; the
   leavings of running a gate (`__pycache__`…) are not edits. The same check
   runs after every non-live gate run in the task's own checkout, red-first or
   judge's own (the keeper's combined-tree re-run is the driver's scratch
   checkout and is not checked this way): a gate that moved HEAD ends the card
   out of scope naming the gate with the tree removed; a gate that wrote outside
   the files ends it out of scope with the tree kept as evidence; no builder
   round is charged either way.
10. **gate** — the exit code decides, once step 9 has checked the run's writes. One failure leaves the task open; the second
   identical failure marks it for re-slicing.
11. **diff review** — a fresh reviewer reads the change with the goal in hand.
    A rejection is a finding list, not a verdict on the task: the task goes
    back to `todo` with the findings (`rejections`) and its worktree
    (`rebuild_from`), the next round first moves that worktree to the current base (its uncommitted edits carried along), then builds in it with the
    findings at the top of its prompt, skips red-first, and skips the contract review ONLY while `contract_seen` still matches the current prompt's digest — a contract edited after its acceptance is one nobody has read, so it goes back to the reviewer
    (both passed before round one), and faces the gate and a fresh diff review
    again. If that worktree is gone, or its edits conflict with what landed, or its base is no longer on the branch, it is discarded and the round runs red-first and the contract
    review again in a fresh checkout, records the replacement, and the round
    count stands. Three rounds in all (`REBUILD_ROUNDS`); the third rejection marks it
    `rejected` for a person. Before this edge existed every rejection was a
    dead end, and the first campaign's four rejected tasks were salvaged by
    hand — the loop must build, not the commander.
12. **keep** — for a CODE card, the candidate tree is proved beside this card's
    gate, the six most recently kept CODE cards' gates, and the gate of any card
    whose own files this one edits, however long ago it was kept (bounded
    regression coverage, not full proof — a clash follows the capped rebuild path);
    a live card's gate acts on the stack and ran alone, so none is re-run. Then
    the commit lands on the campaign branch; the next worktree is cut from that
    tip, never from a HEAD that predates its dependency. The card's files are
    merged onto the tip from the base its worktree was cut from, so a change
    another card kept in the same file meanwhile survives; a clash that git
    cannot merge refuses the keep and parks the card for a person, rather than
    publishing one card's work with the other's quietly gone.
13. **doctor** — after each turn's lanes finish, the loop checks itself for the mistakes it has
    already made, and writes what it finds where the dashboard shows it first.
    Paid-for work that was never kept is its worst complaint; a person answers
    it by slicing the task (the successor carries the findings and the old
    worktree as prior art) or by a `dropped` event that says why — a drop
    without a why stays a complaint.

Every ending writes a status the picker will not re-offer — except a rejection
under its round cap, which is offered again on purpose; a harness fault
after paid work (a call that ran out of time, crashed or answered malformed, a
diff or contract review that answered but not in the shape asked — never one
whose reviewer was never reached; that spends no round, below), which continues in the SAME worktree as a
counted rebuild round, told what happened — a diff review that did not happen
also writes down the phase that DID finish (`finished`: the tree, the base it
started from, the contract's digest and the diff), so the retry re-runs only the
review and calls no builder, while any difference in those four drops the record
and runs the ordinary path
(never on a live card: its round is held for a person either way);
the kept tree is advanced to the current base before reuse, and only its loss, an edit conflict or a diverged base cuts a fresh tree, without changing the round count; and a resource refusal that provably spent nothing and changed
nothing (a usage limit, an expired session, a model at capacity, or a review
whose reviewer was never reached), which stays
todo so the queue stands; every step is timed;
every prompt, answer, diff and gate output is a numbered file under
`calls/<task>/`.

## What it refuses to do

- Raise effort just because a gate failed — that means the task is wrong, not
  the model too small, and costs no rung. Rebuild rounds and replans move
  effort toward xhigh for a builder and high for a reviewer; `max` is never
  used.
- Stop because one resource ran out. Every part that spends a resource walks the
  same belt, so an expired account, an exhausted one or a model at capacity is
  replaced rather than fatal — and a resource that answered is never asked twice
  for the same work.
- Count a usage limit as failure, or throw paid work away on a harness fault: a
  killed reviewer or a malformed answer spends a counted round in the kept
  worktree, and only the round cap ends the card.
- Stop the campaign for one bad task — it quarantines and carries on. It never
  stops itself: hours of work, or a ceiling of answered attempts, since the last
  progress (accepted work, a queued rebuild, or a passed gate) raise an alert the
  `--check` flag shows, once until the next progress, and only `stop.flag` stops
  the campaign.
- Touch the main branch, force-push, or start anything a human holds.
- Trust its own memory: everything is re-read from files, so any part can be
  killed and restarted at any time.

## Known, non-blocking (astra rounds 3 and 4)

Astra's round-3 review named these two and did not block on them; round 4 read
the same code, found both still open, and did not block on them either (its
non-blocking 17 and 18). They are written down here, still not built, so the
next reader finds them without re-reading the review.

- **Two different failures can read as one spin.** `lib/loop_judge.py:53` keeps
  only the last 400 characters of a gate's output as the failure's `why`, and
  `lib/watchdog_spin.py:55` builds the spin signature from task, step and that
  text alone — no contract revision. Two unlike failures that end in the same
  words are counted as one. Astra's fix: record a full normalized evidence
  signature plus the revision, keep the whole finding, and have
  both readers share that one signature.
- **A discarded answer reads as a current decision.** `lib/view_decisions.py:70`
  renders a DROP the same whether it was applied or thrown away as stale.
  Astra's fix: tell applied, pending and discarded answers apart in the shared
  view, and order them by the time each was recorded.

## Running it

```sh
drive-goal.py init --backlog <file> --goal "..." --source <path>   # nothing runs yet; one --source per approved path the slicer may read
drive-goal.py approve                              # the safety catch
nohup bash supervisor.sh &                            # run, restarted, snapshotted
bash watch.sh                                      # the window (Ctrl-C to stop)
bash watch.sh --check                              # red flags only; exit 1 if any
touch <campaign>/stop.flag                         # the off switch — a file, not a kill
```

The campaign lives in `scratchpad/drive-campaigns/current/` and is committed:
the log is the product.

## Reusing it for other heavy work

The logic is generic; where the work lives is four environment variables read by
`lib/where.py`, and what it may spend is three more read by `lib/resources.py`:

```sh
export DRIVE_REPO=/path/to/the/other/repo
export DRIVE_CAMPAIGN=$DRIVE_REPO/scratchpad/drive-campaigns/current
export DRIVE_BACKLOG=$DRIVE_REPO/backlog.yaml
export DRIVE_BRANCH=campaign/that-work

export DRIVE_ACCOUNTS="work,second=/cfg/second,spare=/cfg/spare"
export DRIVE_BUILDERS="claude-opus-5,claude-sonnet-5"
export DRIVE_REVIEWERS="gpt-6-astra,gpt-5.6-sol"
```

Name only models the agent will actually load: an invented name costs the loop
that resource until someone notices. The supervisor asks `lib/where.py` for the
campaign rather than deriving it from its own path, so it and the driver cannot
end up watching different ones.

Then: copy `drive/` into the new repository (or leave it here and
export the variables), write the backlog, `init`, `approve`, start `supervisor.sh`.

**Atomising the heavy work is the real job**, and it is a method, not a feeling:

1. Write the end state as gates first — commands that fail today and whose exit
   code will say the work is done. No task exists before its gate does.
2. One idea per task. If describing it needs the word "and", it is two.
3. The file list is everything the gate can fail on — counts, fixtures, owner
   rows, pinned digests, sibling copies — and never the test that judges it,
   unless writing that test is the declared deliverable.
4. Dependencies are only what is real: a task waits for another only if it reads
   that task's output. Measure the backlog by what is startable now; a long
   chain behind one brick is a stalled weekend.
5. Mark what performs live actions (`gate_has_side_effects`), what writes its own
   proof (`gate_files_are_the_work`), and what a person must see first
   (`blocked_by_human`).
6. Let the loop's reviewer refuse your contracts cheaply before any building —
   the first campaign's nine $0 refusals were the backlog being debugged.
7. Expect to re-slice: anything a builder cannot finish in about half an hour is
   too big, and two identical gate failures mean the task is wrong, not the
   model.

## The numbers from the first day

Pilot: 3 contract refusals at $0, then one task end to end in 105 s for $0.19.
First campaign: 9 tasks refused at $0 — the backlog was the defect, not the
models. After the gates were rewritten to prove behaviour: first accepted commit
(a roster spec that was missing four principals the seed held).
Reviews are ~70–99% of the clock; that is the price of refusing early, and the
lever for speed is better task contracts, not faster builders.
